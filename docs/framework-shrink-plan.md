# תוכנית כיווץ התשתית

המטרה: תשתית שמחזיקה רק את מה שבאמת משותף, וכל השאר יושב במשחק שלו.
התוכנית ממשיכה את [`MIGRATION.md`](../MIGRATION.md) ושומרת על החוקים שלה:
ענף קצר לכל צעד, `npm run check` ובדיקות הדפדפן של מה שנגעו בו, מיזוג
ל-`main`, ובדיקה בטלפון אמיתי אחרי כל צעד שנוגע בשמע. אף צעד לא משנה
את מה שהילד רואה או שומע.

- [x] צעד 1: החבילה הישנה הוסרה
- [x] צעד 2: כל קובץ בתיקיית משחק נשמר לאופליין
- [x] צעד 3a: קופסת הניקוד עברה ללימוד ניקוד (ו-200 שורות CSS של מעטפת האפליקציה הוסרו)
- [x] צעד 3b: מהדר בנק הצלילים עבר לאולפן
- [ ] צעד 3c: ניתוח הקול עובר ל"אמור את הניקוד" (נוגע בשמע; בדיקה בטלפון עם מיקרופון)
- [x] צעד 4: העורך והאזורים הוסרו, וגם zod
- [ ] צעד 5: ההקלטה עוברת לאולפן (נוגע בשמע; בדיקה בטלפון)

## מה נשאר משותף

רק מה שיש לו שני משתמשים לפחות, או שהוא עמוד השדרה של כל המשחקים:

- **מעטפת ומחזור משחק:** `bootstrap`, `game-shell`, `round-manager`,
  `round-scope`, `choice-round`, התקדמות, מסכי טעינה, סיום ושגיאה, משוב.
- **שמע עברי:** `tts`, `audio-context`, `hebrew-audio`, `phoneme-synth`,
  `voice-store`, `sounds`, באנר השמע, וניקוד אוטומטי (`nakdan`).
- **אופליין וקטלוג:** `sw.js`, `catalog.js`, מניפסט הגרסה.
- **קלט:** גרירה ונעילת זום.
- **נתוני עברית:** אותיות, ניקוד, תנועות, עידוד.

## החלטות (התקבלו ב-2026-10-12)

1. **אזורים (Zones): מסירים.** העורך יודע לצייר אזורים על תמונה, ויש
   נגן אזורים, תבניות ו-CSS, ביחד כ־1,100 שורות. אף משחק לא מנגן
   אזורים, אבל כפתור "אזורים" מופיע בעורך, כך שמורה יכול לצייר אזורים
   שלא קורה איתם כלום. אם בעתיד ייכתב משחק אזורים, הוא יחזיק את הקוד שלו.
2. **ממשק העריכה: מסירים.** בלי האזורים, כ־1,400 שורות TypeScript בשביל
   שני משחקים (התאמת אותיות וניקוד). טעינת תוכן שכבר נשמר
   (`core/game-data`, `core/editor-storage` והסכמות) נשארת, כי `CLAUDE.md`
   מחייב לשמור את מפתחות `alefbet.editor.*`. מכשיר שיש בו תוכן ערוך
   ימשיך לשחק בו.

## הצעדים

### צעד 1: הסרת החבילה הישנה (זה צעד 6 ב-MIGRATION)

**ענף:** `chore/drop-legacy-bundle` · **סיכון:** נמוך

- מסירים את בניית `alefbet.js` ו-UMD מ-`framework/vite.config.js` ואת
  הקריאה אליו ב-`scripts/build.js`. הקובץ עצמו נשאר, כי הגדרות vitest בו.
- מוחקים את `framework/src/index.ts` ואת `ui/app-shell.js` ואת הבדיקות
  שלהם, ומעדכנים את `main`, `module` ו-`exports` ב-`framework/package.json`.
- לפני כן מוודאים ש-`@alefbet/framework` לא פורסם ל-npm ושאין צרכן חיצוני.
  בתוך ה-repo אף דף ואף בדיקה לא טוענים את החבילה, וה-service worker כבר
  מדלג עליה.

**סימן שסיימתם:** `npm run verify` ירוק, ב-`framework/dist` אין קבצי
`alefbet.*`, ושינוי קטן בתשתית מייצר הבדל קטן ב-dist.

### צעד 2: משחק יכול להחזיק יותר משלושה קבצים

**ענף:** `chore/game-folder-assets` · **סיכון:** נמוך עד בינוני

היום רק `index.html`, `game.js` ו-`game.css` של כל משחק נשמרים לאופליין
(`scripts/build-release.js`). זה מכריח קוד שעובר לתוך משחק להיכנס לקובץ
אחד. משנים את המניפסט כך שיכלול כל קובץ בתיקיית המשחק.

**סימן שסיימתם:** הבדיקות ב-`service-worker.test.js` ו-`pwa.spec.js`
ירוקות, ונוספה בדיקה שקובץ נוסף בתיקיית משחק נשמר לאופליין.

### צעד 3: קוד של משחק אחד חוזר למשחק שלו, משחק אחד בכל ענף

**סיכון:** נמוך לכל ענף. אין שינוי התנהגות. הבדיקות של המודול עוברות
איתו, כמו `long-exercise.test.js` שכבר בודק קוד מתוך תיקיית משחק.

| ענף | מה עובר | לאן | היקף |
|---|---|---|---|
| 3a `chore/nikud-box-to-game` | `ui/nikud-box.js`, `ui/nikud-glyphs.js`, וקטע ה-CSS "Nikud Box" | `games/nikud-match/` | כ־90 שורות JS וכ־265 שורות CSS |
| 3b `chore/sound-bank-to-studio` | `audio/sound-bank-compiler.js` | `games/sound-studio/` | כ־150 שורות |
| 3c `chore/vowel-detector-to-game` | ניתוח הקול מתוך `audio/vowel-detector.js` | `games/nikud-speak/` | כ־195 שורות |

ב-3c נתוני התנועות (`VOWEL_TEMPLATES`, `NIKUD_VOWEL`) נשארים בתשתית,
בקובץ `data/vowels.js`, כי גם `phoneme-synth` ו-`hebrew-audio` משתמשים
בהם. הענף נוגע בשמע: אחרי המיזוג בודקים את "אמור את הניקוד" בטלפון
אמיתי, עם מיקרופון.

### צעד 4: הסרת ממשק העריכה, כולל האזורים

**ענף:** `chore/remove-editor` · **סיכון:** בינוני

- מוחקים את `framework/src/editor/`. `core` משתמש רק בטיפוסים מתוך
  `editor/schemas.ts` (בדיקת התוכן השמור היא חוזה `editor.content` של
  כל משחק), ולכן הטיפוסים עוברים ל-`core` בלי zod, ו-zod יוצא מהפרויקט.
- מוחקים את `core/lazy-editor.ts`, את כפתור העריכה בתפריט המבוגרים, את
  `ui/zone-player.js`, את `ui/interactive-zones.js`, את קטע ה-CSS
  "Interactive Zones", ואת כניסת `editor` ב-`vite.runtime.config.js`
  (ואיתה `editor.js` ו-`editor.css`).
- שדה `zones` נשאר מותר בתוכן שמור, כדי שתוכן עם אזורים ממשיך להיטען.
- בדיקות: מוחקים את בדיקות העורך, ומוסיפים בדיקה שתוכן שמור (גם עם
  אזורים) עדיין נטען בשני המשחקים. מעדכנים את בדיקות הדפדפן שפותחות את
  העורך (`letter-match-animals`, `pwa`, `mobile`).
- מעדכנים את `CLAUDE.md`: הכללים על העורך ועל `editor.content` מתקצרים
  לטעינת תוכן שמור בלבד.

### צעד 5: ההקלטה עוברת לאולפן הצלילים

**ענף:** `chore/recorder-to-studio` · **סיכון:** נמוך

אחרי צעד 4 רק האולפן מקליט. `audio/voice-recorder.js` ו-
`ui/voice-record-button.js` עוברים ל-`games/sound-studio/`.
`voice-store` נשאר בתשתית, כי `hebrew-audio` מנגן ממנו את ההקלטות בכל
המשחקים. אחרי המיזוג בודקים הקלטה והשמעה בטלפון אמיתי.

גרירה (`input/drag.js`) תישאר אז עם משתמש אחד, לימוד ניקוד. היא נשארת
בתשתית כמו נעילת הזום, כי היא התנהגות קלט כללית; אם לא יופיע משתמש שני,
אפשר להעביר גם אותה.

### צעד 6: הערכה מחדש של dist ב-git

אחרי צעד 1 רוב הרעש בקבצי הבנייה נעלם. רק אם עדיין מפריע, מוציאים את
`framework/dist` מ-git בגרסה מצומצמת: הפריסה כבר בונה בעצמה, ו-`start.js`
בונה כשאין dist. זו לא כתיבה מחדש של האתר ב-Vite.

### בסוף: תיעוד

מעדכנים את פרק המבנה ב-`CLAUDE.md`, את רשימת המצב ב-`MIGRATION.md` ואת
`docs/adding-games.md`.

## מה לא עושים

- לא מעבירים קוד למשחק ומשנים אותו באותו ענף. קודם מעבירים, אחר כך משפרים.
- לא מוסיפים לתשתית משהו חדש במהלך הכיווץ. גם לא את פונקציית ההקראה
  עם הגבלת זמן מ"סיפורי בלונים"; היא תעבור לתשתית כשמשחק סיפור שני ייכתב.
- לא נוגעים ב-`sw.js` מחוץ לצעד 2.
- לא ממירים JS ל-TypeScript בדרך.
