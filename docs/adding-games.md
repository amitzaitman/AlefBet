# הוספת משחק ל-AlefBet

## גבולות האחריות

המשחק מחזיק תוכן, חוקים, רמזים, רמת קושי ורינדור. מודולים ונכסים של משחק אחד
יושבים בתיקיית המשחק; כל קובץ שם נשמר לאופליין. התשתית מספקת מעטפת,
קלט, משוב, מחזור חיים ושמירת תוצאות. הוספת משחק רגיל משנה רק את תיקיית
המשחק ואת הקטלוג; הבנייה מעדכנת אוטומטית את רשימת נכסי האופליין.
רכיב חדש מחלצים כשיש לפחות שני משתמשים עם אותה התנהגות.
איך התשתית עצמה עובדת (שמע, אופליין, בדיקות ופרסום) מוסבר ב-[architecture.md](./architecture.md).

## התחלה מהירה

`npm run new:game -- my-game "שם המשחק"` יוצר שלושה קבצים ורושם בקטלוג.
מפעילים `node start.js` ופותחים `/games/my-game/`. התבנית היא משחק בחירה
עובד, שאפשר להחליף את תוכנו או את כל `buildRound` שלו.

כל משחק מייבא מ-`framework/dist/runtime.js` ומשתמש ב-`runtime.css`. משחק ללא דיבור
מגדיר `audio: false`, כך שלא מוצג באנר הקול ולא מתבצע שחרור קול בנגיעה הראשונה.
צלילי הצלחה עדיין זמינים דרך `sounds` ו-`createFeedback`. טקסט עברי נכתב מנוקד בקוד המשחק.

הכניסות מייצאות רק מה שמשחקים כבר משתמשים בו. משחק שצריך רכיב קיים שלא
מיוצא מוסיף אותו ל-`framework/src/runtime/index.js` ומריץ `npm run build`. בדיקות יחידה ללוגיקה של המשחק
נכתבות ב-`framework/src/__tests__/` ומייבאות מתיקיית המשחק, כי כל קובץ
בתיקיית המשחק נשמר במכשיר.

משחק חשבון נבנה לפי [עקרונות למשחקי חשבון](./math-pedagogy.md): סיפור, תמונה
ותרגיל שכל אחד מהם מספיק לבד. `balloon-stories` הוא הדוגמה המלאה, כולל קריינות.

## שלוש אפשרויות להרכבה

1. בחירת תשובה: `runGame` עם `createChoiceRound` (השלמה לעשר).
2. סיבוב עם ממשק ייחודי: `runGame` עם `buildRound` מקומי (ציר המספרים).
3. פעילות חופשית: `bootstrapGame` ללא מנהל סיבובים, לדוגמה:

```js
import { bootstrapGame, createRoundScope } from '../../framework/dist/runtime.js';

export async function startGame(container) {
  const result = await bootstrapGame(container, {
    gameId: 'explore', title: 'חוקרים מספרים', audio: false,
  });
  if (result.aborted) return result;
  const { shell } = result;
  const scope = createRoundScope();
  shell.on('end', () => scope.dispose());
  const button = document.createElement('button');
  button.textContent = 'הוספת קובייה';
  shell.bodyEl.append(button);
  scope.listen(button, 'click', () => { /* חוקי הפעילות כאן */ });
  return result;
}
```

## מחזור חיים וקלט

בכל סיבוב רושמים רכיבים עם `scope.use`, מאזינים עם `scope.listen` וטיימרים
עם `scope.schedule`. פעולות אסינכרוניות מקבלות `scope.signal` אם הן תומכות
בביטול; אחרי `await` בודקים `isActive()` לפני שינוי מצב. פעולות ארוכות בלי
יכולת ביטול אינן נחסמות אוטומטית על ידי התשתית.

`onCorrect` ו-`onWrong` מנהלים נעילה, ניקוד ומעבר. בממשק מותאם משתמשים
ב-`isAnswered()` וב-`subscribeAnswered` כדי למנוע תשובות כפולות. אל תנהלו
מונה ניקוד נוסף במשחק. אתחול באותו מיכל מסיים את המשחק הקודם.

מסך משחק לא מתקרב בהקשה כפולה או בשתי אצבעות: `GameShell` נועל זום, וגלילה
באצבע אחת נשארת. דף בלי `GameShell` קורא ל-`lockPageZoom()`.

גרירה משתמשת ב-`createDragSource` וב-`createDropTarget`, הרשומים ב-scope.
המשחק קובע אם ההנחה נכונה. ספקו גם חלופת לחיצה/מקלדת; ראו `nikud-match`.
כפתורים בגודל 64 פיקסלים לפחות. במשוואות ובציר מספרים הגדירו `dir="ltr"`
בתוך העמוד העברי כדי שסדר המספרים והפעולות יישאר נכון.

## בדיקות והפצה

הוסיפו בדיקת דפדפן לתשובה נכונה, ניסיון נוסף, סיום והפעלה מחדש. לאינטראקציה
חדשה בדקו גם מגע ומקלדת. משחק חדש צריך לעבוד בכתובת הישירה ובמצב אופליין
אחרי התקנת המטמון. הוסיפו בדיקות ליצירת התרגילים אם יש בהן לוגיקה לא פשוטה.

מריצים `npm run verify`. הפקודה בונה מחדש ובודקת הכול; מחייבים גם dist.
לבדיקת המשחק בלבד: `npm run e2e -- e2e/math.spec.js` (כולל בנייה אוטומטית).
התקנת דפדפנים ראשונית: `npm run setup:browsers`.
הבנייה שומרת את כניסת ה-runtime ואת תלויותיה במטמון המשותף; זו אינה
התקנה נפרדת לכל משחק. בדיקת דפדפן אוטומטית אינה מחליפה בדיקת שמע בטלפון אמיתי.

### בדיקות אופליין

כל spec מייבא `test` ו-`expect` מתוך `e2e/network-server.js`. יש שם גם
`activate` (הקשה בטלפון, לחיצה במחשב), `noVoice` (בלי קול מערכת, ואפשר גם בלי
רשת) ו-`expectTouchTargets` (מטרות מגע של 64 פיקסלים). לבדיקת אופליין משתמשים
בשרת המבודד של הבדיקה:

```js
await page.goto(`${network.url}/games/my-game/`);
await network.reloadOffline(page); // כאן בודקים שהמשחק עובד מהמטמון
```

העזר מחכה ל-service worker פעיל, מנתק שרת אמיתי, מתאים את עצמו ל-WebKit
ומחבר מחדש בסוף הבדיקה. אין להעתיק `setOffline`, בדיקות חיבור או ניהול
sockets לתוך spec. בקשה תקועה אינה הוכחה לניתוק: העזר דורש שגיאת רשת מפורשת.

### המתנות קבועות במשחק

מעבר בין סיבובים, משפט בסיפור או הפסקה בין שלבים הם טיימרים קבועים, ובדיקה
לא צריכה לחכות להם בזמן אמת. מתקינים `await page.clock.install()` לפני
`page.goto`, ואחרי פעולה מריצים `await page.clock.runFor(1600)` בגודל
ההמתנה של המשחק. מריצים את השעון רק אחרי בדיקה שמוכיחה שהפעולה נקלטה (למשל
שהכרטיסים ננעלו או שהמונה התקדם), אחרת הטיימר עוד לא נקבע. משאירים לפחות
בדיקה אחת לכל משחק עם קריינות בזמן אמת, כמו בדיקת "בלי קול" של `balloon-stories`.

### סיווג בדף הבית

לכל משחק מגדירים `category` ב־`games/catalog.js`:‏ `reading` לקריאה ושפה,
`math` לחשבון או `other` לתחום אחר. `topic` הוא תיאור קצר ואופציונלי שמופיע
על הכרטיס, למשל שברים. תחומי הלימוד והסדר שלהם מוגדרים ב־`ALEFBET_CATEGORIES`.
דף הבית מציג רק תחומים שיש בהם משחקים; משחק ללא סיווג מוכר מופיע ב״עוד משחקים״.
כלי הורים ומורים נשארים נפרדים באמצעות `kind: 'teacher-tool'`.
